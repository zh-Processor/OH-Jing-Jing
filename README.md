# OHJingJing

OHJingJing 包含可独立使用的 Windows 桌宠和常驻 QQ 群聊服务。桌宠使用个人模型凭据聊天和陪伴，可在同一工作区连接多个群聊服务，读取获准的消息、摘要、画像和功能入口。群聊服务独立处理 QQ 收发、摘要、画像、主动聊天和账号动作。

- [设计、架构与当前研发进度](OHJingJing-机器人平台设计方案.md#当前交付状态)
- [历史验收记录](docs/历史验收记录.md)

## 安装和首次使用

1. 使用 Windows x64 标准测试包，或选择内置 WebView2 安装程序的离线测试包。构建产物通过测试发布通道单独提供，也可以从本仓库源码构建。
2. 启动应用并点击「显示桌面宠物」。默认角色为大肥鱼，投喂、摸摸和休息可直接操作。
3. 在「设置 → 个人模型与 API Key」保存个人模型档案并测试连接。连接通过后可直接点击桌宠对话。
4. 需要群动态时，在工作区为每个服务分别填写地址和订阅令牌。群摘要与已发布画像可直接读取。个人对话和讲解使用桌宠配置的个人模型。

## 本地运行

- Node.js 22.20 或更新版本。
- 构建 Windows 桌宠还需 Rust MSVC 工具链和 Tauri 的 Windows 开发依赖。
- 发布脚本支持指定产物目录。本地构建产物与私有配置由各自安装环境管理。

```powershell
npm ci
Push-Location pi-workspace
npm ci --ignore-scripts
Pop-Location
npm run check
npm test
npm run dev
```

在设置中配置自己的兼容模型接口后，点击「显示桌面宠物」。再点击桌面上的角色，即可直接输入并在角色旁看回复。桌宠与主窗口共用个人聊天历史。群动态和模型配置在主窗口打开。角色可导入 JSON，字段为 `id`、`name`、`version` 和 `persona`，可包含 `personality`、`examples` 和 `avatar`。头像接受 `data:image/png;base64,...`，最大 512×512，编码后不超过 96 KB。没有头像的角色使用默认图形。密钥使用 Windows 凭据库。运行 `npm run build` 生成桌面安装包。

更换模型供应商或群动态服务地址时，填写新地址的 API Key 或订阅令牌。新凭据写入 Windows 凭据库后才会生效。凭据库拒绝写入时，原配置仍可使用。旧版保存的凭据可在原地址继续使用。

### 工作目录和网页查询

桌宠对话使用本机模型档案。群聊、好友私聊、摘要和画像使用服务端档案。工具由当前运行时编排，回复沿原会话投递。

- 从桌宠「设置 → Pi 工作区」选择工作目录，打开内置的原生 Pi 终端。首次使用时在 Pi 中运行 `/login` 和 `/model`。自定义兼容端点在该 Pi 配置目录的 `models.json` 设置。这套凭据和会话独立于桌宠与服务端的模型档案。
- 工作区可使用原生会话、恢复、分支、压缩、文件与搜索工具、Bash、PowerShell、扩展、技能、提示模板、主题、MCP 和 Pi 包。额外工具可在 Pi 的 `settings.json` 中用 `defaultTools` 配置，例如 `["+powershell", "+grep", "+find", "+ls", "+codemode", "+tool_search"]`。工作目录是命令的起点，权限与当前 Windows 帐户相同。
- 桌宠对话输入 `/搜索 搜索词` 或 `/读网页 https://example.org/`。QQ 群在指令前 @ 或点名，已授权好友可直接在私聊输入。网页查询只向 Exa MCP 提交本条请求指定的搜索词或地址。Pi 在当前回合查找并整理资料，近期新闻使用有发布日期的结果。搜索受第三方服务可用性和限额约束。
- 启用 DSH 的 QQ 对话由 Harness 根据当轮请求选择是否查询公开网页。服务端校验当前发言中的检索片段或公开地址，再把查到的资料交回同一轮生成。群里单独点名时先确认在场，随后可接同一人的补充。最终文字沿原 QQ 会话发送并记录回执。
- QQ 的公开链接分享和 B 站分享卡片可随本条配文进入群聊或私聊。收件只保存公开地址，B 站链接会去掉跟踪参数并保留有效的分集或时间点。要求核对或总结时，Harness 可读取公开页面。仅分享链接时按普通消息处理。
- 服务包内的 `start-pi-workspace.ps1` 面向服务器操作者，可转发原生 CLI 参数。首次使用从包内 `pi-workspace` 目录运行 `npm ci --ignore-scripts`。指定独立的目录保存 Pi 数据，便可用交互终端或 `-PiArguments @('--mode','rpc')`。例如 `./start-pi-workspace.ps1 -Workspace <工作目录> -DataDirectory <Pi数据目录>`。

### 对话上下文与后台整理

- 可在桌宠模型档案和服务端各模型配置设置对话输入预算 `contextBudget`，范围为 4096 到 12000 Token，默认 12000。用启发式估算输入，给回复及工具结果留独立空间。主备模型取两者较小的预算，保留当前消息、直接引用和关键证据，优先裁剪无关资料与较旧的消息。
- 角色卡的对话示例可填 `scene` 和 `intent`。意图支持 `greeting`、`banter`、`follow-up`、`help`、`care`、`history` 和 `opening`。已有角色卡继续可用。相处状态和心情单独参与本轮表达。
- QQ 对话的 Pi 回合可查询当前群已有的授权话题、证据和画像。运营后台「群回复记录」显示本轮采用的资料类型、版本、估算大小与裁剪数量。资料在生成期间更新或撤下时，直接回复提供简短说明，主动候选丢弃。
- 群摘要按批次保留进度及证据。明确撤回的安排显示为撤回，新回复不沿用旧决定。已记录来源的摘要在原文缺失时只向桌宠展示仍可核实的内容。画像更正候选列出新增、更正或撤回及其证据编号，沿用现有发布授权。
- 桌宠把较长的本机对话整理为可续聊检查点，保留最近的原文及用户明确修正的事实。整理任务使用本机模型档案，在本机用量中单独计数，结果保存在本机对应角色的对话数据中。

在「设置 → 个人模型与 API Key」选中已保存的档案，可以清除本机 API Key，也可以移除整个档案。清除 Key 保留模型地址、预算和历史用量，移除档案则保留已记录的历史用量。其他档案对该模型的备用绑定会解除。当前聊天模型被停用或移除时，桌宠会优先选择另一个已有 Key 的档案。Windows 凭据库暂时无法清理时，旧 Key 先从桌宠停用，下次读取设置时继续清理。

在「设置 → 个人模型与 API Key」选择已保存的档案，展开「本机模型预算」。可分别设定每日、每月请求次数和估算费用上限，留空为不限，填 `0` 暂停该档案。主窗口和悬浮桌宠共用额度。个人聊天、摘要和画像讲解、角色试演、连接测试在发出请求时计入次数。备用模型按自己的档案检查和记账。已保存的群动态照常可读，供应商余额仍可独立查询。

日月窗口按北京时间计算。请求次数包含失败、取消和中断的已发起请求。费用按请求发生时档案里的单价与返回的 Token 估算，已设费用上限的档案会等待当前计量结束后才允许再次调用。单次费用可能超过剩余额度。缺少单价或 Token 的请求显示为未计价，仍计入请求次数。更换估算币种时，费用与费用上限按原币种保留，请求次数按档案合计。

需要把聊天、角色和窗口数据放到指定盘时，在启动桌宠的 PowerShell 中设置 `$env:OHJINGJING_DATA_DIR = 'D:\RobotData\OHJingJing\desktop'`，再从同一窗口启动桌宠。填写应用专用目录的绝对路径。该目录用于本机数据库和 WebView2 数据，认证凭据由 Windows 凭据库管理。

### Windows 安装、升级与卸载

标准包可联网准备 WebView2。离线包包含 WebView2 安装程序，使用 `-offline-setup.exe` 后缀。两种包都优先使用系统已有的运行时。构建离线包时在项目目录运行 `npm run build -- --config src-tauri/tauri.offline.conf.json`，生成的安装程序在 `src-tauri/target/release/bundle/nsis`。

在可使用 Windows 界面的测试会话中运行下列验收，将变量替换为实际包路径。指定上一版本可校验覆盖升级后保留角色、记忆、凭据和工作区。单独测试首装与卸载时使用 `--fresh-install`。在无 WebView2 的测试机上使用 `--fresh-webview2`，标准和离线包分别验收。

### 插件中心

桌宠的插件中心分为角色和 IM 渠道。角色分类可以新建本地角色、导入 JSON、切换桌宠角色或预览授权群已发布的角色。IM 渠道显示已订阅服务所用的插件、连接状态和声明的能力。群摘要和历史召回在运营后台的群聊策略配置，桌宠气泡提醒在群动态配置。

大肥鱼是默认角色，包含桌面陪伴、群聊、私聊和资料讲解四类示例，以及七项性格维度和四项心情基线。在「本地角色」选择「复制为本地角色」，即可获得具有独立会话和记忆的副本。「编辑角色」可修改名称、版本、角色设定、PNG 头像和对话示例。

从 0.1.10 起，在「插件中心 → 角色」打开「角色试演」。选择个人模型后，可以模拟桌面陪伴、QQ 群聊、QQ 私聊、投喂等动作后的心情，或按时刻触发的私聊问候。预览显示当前有效的角色版本和指纹、场景、理由、手填样本记忆及回复内容。每次试演调用所选模型一次并按当前档案记账。试演数据来自填写的样本，结果只显示在桌宠窗口。

「导出角色 JSON」使用 Windows 另存为窗口。文件包含角色设定、当前有效人格和角色素材。导入同 ID 的不同版本或内容时，可选择保留原角色并安装独立副本，或更新原角色并继续使用其会话和记忆。内置角色的修改版只能作为副本安装。

在「插件中心 → 角色 → 本地角色 → 调整人格」选择性格档位，展开编辑价值观、兴趣、相处边界、语言习惯和场景规则。预览可切换桌面陪伴、QQ群聊与资料讲解，查看会进入本轮模型上下文的表达规则。保存会覆盖当前设备上这个角色的人格偏好。「恢复角色默认」会重新使用角色自带的设定。

运营者在服务端「插件中心 → 角色」可以选择实例默认角色或群专用角色。实例默认角色用于沿用该配置的群和好友私聊。管理员也可以在已观察的群发布当前角色快照，已领取的版本按内容指纹识别。修改机器人使用的角色后，可另外发布新版。机器人使用角色与群公开快照分别保留最近 30 条可查看的版本记录，回退后记录新版本。

拥有该群订阅权限的桌宠用户可以在「服务端角色」预览，然后选择「跟随该群角色」或「安装桌宠副本」。跟随只用于该群摘要和画像的讲解，沿用桌宠自己的模型 Key。已有跟随保留所选版本，刷新后可预览新发布内容。撤下角色、撤销订阅或更换服务连接后，桌宠在同步时清除跟随。安装到本机的副本继续可用。旧发布记录升级时，以当时可见的角色内容作为首个快照。

角色的 `personality.traits` 可设置 `sociability`、`warmth`、`humor`、`curiosity`、`directness`、`expressiveness` 和 `initiative`，值为 1 到 5 的整数。`values`、`interests` 和 `boundaries` 是字符串列表，`voice` 是语言习惯，`scenes` 用 `desktop`、`group`、`private` 和 `reference` 指定不同场景的规则。`examples` 中的对话示例可带同样的 `scene` 值，也可作为通用示例。两端优先选当前场景的例子，每轮最多加入四个。原有角色 JSON 可继续使用。

### 桌宠陪伴与动画

点击桌上的角色打开气泡，可直接投喂、摸摸或让它休息。这些动作本地运行，分别播放咀嚼、摆动爱心和慢呼吸动画。动作结束后，待机状态会跟随心情逐步恢复。自带角色图形和自定义头像共用动作动画。群摘要提醒使用独立的短时提示。

悬浮桌宠和主窗口共用一轮个人聊天。生成中，两边都可以点击「停止生成」，发起窗口保留输入，方便修改或重试。只有完整返回的问答才会写入会话历史。关闭其中一个窗口时，只要另一窗口仍开着，本轮可以继续。退出整个应用会中断生成，下次启动可在本机模型用量看到中断次数。停止或中断仍计入已发起的请求次数，费用以供应商返回的用量估算。

在悬浮桌宠中点击「群摘要」，可选择授权群，查看最新和近期已发布摘要。浏览使用订阅令牌，个人模型 Key 用于个人聊天和模型讲解。在主窗口「群动态」勾选「此群有新摘要时让桌宠提醒」后，悬浮窗会定期检查该群。首次关注会记录当前摘要作为起点，重新打开时检查离线期间的新摘要。点击气泡可直接查看。

从 0.1.11 起，桌宠会根据已发布摘要区分话题更新、待确认事项、新决定和已确认的变更。普通更新轻轻浮起，待确认时歪头，决定和变更触发轻跳。气泡只显示群名和状态，点开后可查看话题名、对应进展和完整摘要。主窗口的群动态也会突出这条进展。缺少可用证据的旧摘要沿用普通提示。提示使用订阅已返回的数据，个人心情、记忆和模型用量各自独立。

在主窗口「设置 → 桌宠摘要提醒」可暂停气泡、设置按本机时间计算的勿扰时段，以及选择在 Windows 全屏、演示或锁屏时延后。勿扰时段可跨午夜。暂停期间仍可手动查看群动态。待提醒记录随关闭和重启保留。同一个群只保留最新的待提醒摘要，多个群的提醒恢复时合并成一条气泡。显示前刷新订阅，取消关注或撤销访问会清除关联待提醒记录。本机保存摘要编号、时间和提醒状态，摘要正文从服务端读取。

### 桌宠本地提醒

在主窗口选择「提醒」，填写内容和本机时间。主窗口可编辑、完成或取消待办。到期后悬浮桌宠显示气泡，点击可完成，也可延后 5 或 15 分钟。桌宠面板中的「待办」可以手动查看到期项目。

本地提醒使用本机数据库。应用关闭期间到期的待办会在下次打开时显示。勿扰时段和 Windows 全屏延后设置同时适用于本地提醒及群摘要，两类提醒各自有暂停开关。暂停期间仍可手动查看和操作。完成或取消后会从待办列表移除，记录清除正文。

当前心情与熟悉度可在「插件中心 → 角色 → 本地角色」查看和重置。角色包可通过 `personality.mood.baseline` 设置 `joy`、`energy`、`tension` 和 `curiosity` 的 0 到 100 点基线，并以 `recoveryMinutes` 为各项设置 5 到 1440 分钟半衰期。同类陪伴动作间隔为 20 秒。互动状态按本机或群与角色分别持久化。被 @ 后成功回复的会话才增加群内互动记录。

### 桌宠备用模型

在「设置 → 个人模型与 API Key」先保存两个各自带 Key 的档案，再选中主档案并设置「个人聊天备用模型」。主窗口和悬浮桌宠共用此设置。备用档案会在主模型临时故障时接收同一轮个人对话上下文，两次请求共用 25 秒的等待上限。切换时窗口会显示备用模型，实际发出的请求分别计入各档案用量。

「停止生成」会终止本轮，供应商明确拒绝时会提示原因。群摘要和人物画像讲解使用本次确认的模型。备用档案或凭据在生成期间更新后，新配置从下一轮生效。连接测试和余额查询使用当前档案。实际供应商之间的切换可在配置两份个人档案后联调。

### Packy DeepSeek

桌宠设置内可选「Packy DeepSeek 预设」，自动填写 `https://cf.api.fan/v1`、`deepseek-v4-flash` 和 Packy API Key 额度接口。旧档案可在「余额接口」选择「Packy API Key 额度」，保存后点击「刷新余额」。查询显示 Key 的已用额度、剩余额度及查询时间。Key 未设上限时，调用仍受 Packy 账户余额约束。账户余额可在供应商控制台查询。

服务端和桌宠的模型调用统一使用已知兼容路线的最高推理档。DeepSeek 官方与 Packy 的兼容 DeepSeek 模型使用 `max`，OpenRouter 的兼容 DeepSeek V4 模型使用 `xhigh`。聊天、工具回合、摘要、画像、记忆、角色试演、模型测试和自动开发均按实际选中的模型应用对应档位。兼容路线的常规模型回合保留至少 8192 个输出 Token 的额度，供推理和正文共享。未识别的模型路线沿用供应商默认设置。

在桌宠设置中选中已保存的模型档案即可读回当前 Key 的余额或额度快照。更改地址、余额接口或填写新 Key 时暂时隐藏旧数值，保存新配置后按当前凭据重新查询。供应商请求失败时，界面显示本次查询状态和上次成功结果。读取时已超过 15 分钟的成功快照带时间提示。

## 群聊服务

在项目目录复制配置样例，再按实际部署环境填写实例、渠道、模型和群策略。使用隔离的服务账号保存管理员令牌、模型 Key 和网关令牌。

```powershell
npm ci
if (!(Test-Path -LiteralPath .\server.config.json)) {
    Copy-Item .\server.config.example.json .\server.config.json
}
npm run build:server
.\dist-server\start-test-server.ps1 -Config .\server.config.json
```

服务程序构建到 `dist-server`。部署时可使用该目录内的 Windows 启动脚本。运营入口默认在本机回环地址 `http://127.0.0.1:8789`。桌宠连接使用各服务签发的订阅令牌。

服务端的 `channel.pluginId` 选择已注册的 IM 渠道插件，默认使用 `qq.onebot`。连接和授权继续由服务端配置。完成连接配置后，运营后台「插件中心 → IM 渠道」可暂停或启动渠道，状态随数据库重启恢复。暂停会断开网关、取消正在生成的回复，并阻止旧连接的回调。存量群摘要可继续读取，已排队的摘要继续处理。

IM 接口位于 `runtime/im-channel.ts`，统一接收事件、发送回执和登录状态。适配器通过 `runtime/im-plugins.ts` 注册，声明接口版本和支持的能力。QQ 资料及空间操作走独立扩展，服务端按实际能力显示。替换同平台渠道时，历史仍按机器人账号和群保留。微信需单独实现账号接入和业务联调。

配置的 `roles` 可直接加入与桌宠导入格式一致的角色对象。`channel.roleId` 指定默认 QQ 角色，`groupRoles` 用群号映射该群专用的角色 ID。引用未安装的角色会在启动时报告错误。

复制 `server.config.example.json` 为 `server.config.json`。群聊回复、观察和摘要分别由 `channel.groups`、`observeGroups`、`summaryGroups` 控制。启用群摘要前确认群内知情，并确认选定模型可以处理摘要样本。将群聊服务连接到已授权的 OneBot v11 WebSocket 网关。填写 `channel.expectedBotId` 为机器人 QQ 号（字符串）时，单实例和多实例都会在收发前核验网关登录账号。后台的「检查 QQ 登录」可核对当前匹配结果。管理员令牌、OneBot 令牌和模型 Key 通过本机进程环境配置。

QQ 渠道每轮检查结束后等待 20 秒，再核对 WebSocket 心跳和网关在线状态。心跳五秒内无对应应答、网关明确报告离线或异常、已配置账号无法核验时，服务关闭该连接并重新连接。断线时取消尚在生成的群聊回复，并清除短时接话状态。断线前已提交、缺少明确回执的发送标为结果未知，重连后只处理新请求。QQ 登录由网关维持。

在「插件中心 → IM 渠道」可查看最近发现的连接故障，或点「检查 QQ 登录」核对当前账号。界面分别显示连接凭据被拒绝、已登录账号不符、登录未核验、QQ 离线或异常、WebSocket 心跳超时及一般连接故障。账号核验通过后清除故障提示。订阅者继续使用群动态的在线和覆盖信息。

首轮实机联调使用独立运行的 QQ 网关。后台的「检查网关能力」查询 OneBot 版本和空间扩展的响应情况。空间查询成功后仍需实测发布权限与可见范围。替代网关使用同一接口与测试用例验收，群聊数据继续使用原数据库。

候选 QQ 渠道可以在独立实例设置 `channel.pluginId` 为 `qq.milky`。填写预期 QQ 账号、HTTP 网关根地址和已配置的渠道令牌。网关地址须使用 HTTPS 或本机回环 HTTP。使用独立收件时，收件配置也选择同一 `pluginId`，并为候选协议使用独立收件数据库。后台展示已接入的收发和资料能力。需要实际 QQ 登录、送达读回和空间能力验收后才能安排切换。

候选 HTTP 网关提供空间操作时，实例可将 `channel.qqAccountContract` 设为 `ohjingjing-v1`。网关通过 `get_impl_info` 声明账号、版本和支持的动作。服务按已核验登录、声明能力和后台权限处理空间操作。接口字段见设计方案的 QQ 网关验收一节。

管理员刷新状态后可在「群聊策略」保存观察、回复 @、摘要和历史召回。已配置机器人 QQ 号时可直接输入群号。后台策略按账号与群号存入服务端数据库，即时生效并在重启后保留。配置文件为尚未保存后台策略的群提供默认值。全局暂停继续覆盖群回复。观察会记录活动统计，启用摘要后才保留供摘要使用的文本。桌宠订阅在群收到事件后可开通，关闭观察会隐藏该群的订阅数据。

群内主动聊天在运营后台按群设置。开启群观察和回复后，可选关闭、仅预览或自动发送。多人讨论时，机器人可以接话、回复一个表情或保持沉默。热聊时使用较短的间隔，安静时可以按设定尝试主动开题。同一群每天最多触发一次空闲开场，接话和开场共用每日生成额度，受静默时段、冷却和群暂停控制。

开场生成遇到暂时限流、超时或供应商连接故障时，同一天内可为这次开场重试一次。至少等两分钟，再按当前群的空闲时间、冷却、静默、权限、费用预算和每日生成上限判断。重试重新读取当时有效的话题，另记一次生成和模型用量。服务重启会保留等待中的重试。遇到角色主动沉默、凭据错误或已有发送记录时结束该次开场。

开场生成期间如果本群新增了授权计划或日记话题，旧候选会丢弃，并可在同一轮的重试限额内重新判断一次。重试时须仍有新的授权话题，重新读取有效标签，沿用该群的空闲、静默、冷却和预算规则。撤回新授权后，本次开场仍按原次数结算。

按群开启空闲开场后，可勾选「允许从本群角色包的兴趣选开场话题」。在「定时群提醒」中填写「开场话题」可授权使用该计划的简短话题。系统最多参考三项未来七天内未暂停的本群计划，只把授权话题名称交给模型。清空话题或暂停计划即可撤回。发送前会再次核对相关资料是否仍有效。

勾选「接续刚回复的群友追问」后，同一群友在机器人确认发出回复后的 45 秒内，可以用「那改成周日呢」「再短一点」一类短句接续。每轮最多判断两次，模型确认是同一话题后才继续。45 秒用于判定收到追问的时间。已接收的追问有独立的 15 秒候选处理时限，其他人插话会结束这段接续。追问沿用群的预览或自动发送模式，并计入每日上限和服务端预算。待确认改期保留原时间并用问题核对。明确 @ 继续优先处理。

接话和空闲开场共用主动发言冷却。免 @ 追问有自己的接续窗口。距离上次提交群消息发送不足 45 秒时，普通讨论保持安静。热聊中的这段间隔为 20 秒。

运营后台「群内主动聊天 → 试演自然接话」可为当前选中的群输入 2 到 6 条样本，每行填写「称呼：发言」。试演沿用当前角色版本、群心情、最低发言人数和该群生效的模型路由，显示接话、表情或保持沉默。实时群消息、画像和归档均排除在样本之外。提交的发言会发给配置的模型，结果只显示在当前后台页面。模型调用按「群接话试演」计入后台预算及用量。试演期间实际群聊仍按原设置运行。

收到明确的 @ 时走独立回复路径。启用回复且网关可用时，每条去重后的 @ 都会回复。模型临时失败或选择沉默时，应用发送简短应答。主动聊天的预览文本、跳过原因和发送记录可在运营后台查看。

群聊会区分不同群友的发言。句首明确点名或引用机器人已确认发出的消息也会触发直接回复。直接回复会等待最多 600 毫秒，最多合并同一人紧接着发的三条普通补充。其他人插话或遇到下一条定向消息时结束合并。引用先从同群已确认的回复和近期消息定位，启用摘要后还可以查找保留期内已归档的原文。只提议换日期时，如果引用里只有一个明确时间，回复会带上原时间作为待确认项。群聊角色会抓住玩笑里的具体细节，遇到认真问题直接作答。发送前会清理常见的括号动作描写。图片未读取时会明确提示。

群聊直接回复可选择一条或两条完整的消息。清单和代码块作为一条消息保留。第一条确认发送后才尝试第二条，群暂停或网关失联时结束本轮。每条消息独立保存回执，后续对话只使用确认发出的内容。多条消息共用本轮的一次模型请求。

大肥鱼有微笑、赞同和鱼梗三种预设。服务端可通过 `roleExpressions` 按角色 ID 覆盖预设。每项包含 `id`、`label` 和 `emoji`，还可填写一个 `qqFace` 编号，或在 `png` 放入不超过 96 KB、边长最大 512 像素的内嵌 PNG。支持的备用表情为 🙂、👍、😂、👀、🤔、🎉、🐟、😅、❤️。需要关闭某个角色的表情时，将该角色的预设设为空列表。

在开启观察和回复的 QQ 群，同一条消息附 `/收藏表情 早安` 和一张不超过 256 KB 的图片或表情包。地址失效时会尝试重取。用 `/找表情 早安` 查编号，或用 `/找表情` 查看最近八张，再用 `/发表情 编号` 在本群发送。收藏者或机器人主人可以用 `/删除表情 编号` 移除。每群最多保留 40 张，重复图片沿用原编号和标签，保存期限随群消息保留设置。

启用 Harness 工具的群也可以直接问大肥鱼「本群收藏里有鼓掌的表情吗」或「把本群收藏的鼓掌表情发一下」。普通对话继续走原回复流程。查找只读取同群标签和编号，发送前重新检查收藏是否可用。图片已删除、过期或网关明确拒绝发送时，机器人会说明情况。网关回执不明时保留待核对记录。

群聊可把合并转发和 @ 放在一条消息里，也可 @ 大肥鱼并引用自己刚发的转发卡片。已获准的好友私聊可随问题附上卡片。每轮优先展开最近两张内层卡片，最多展开一层，取末尾最多八段文字供本轮回复。节选里的链接、联系方式和数字标识会脱敏。内层未展开时，大肥鱼会按已读内容说明能核实的范围。

QQ 看图回合可以直接问「图里写了什么」或请大肥鱼抄出指定文字。启用视觉档案的 Windows 服务会先用本机 OCR 读取最多两张已关联的图片，并把按图编号的识字结果交给当前视觉模型核对。系统识别器不可用、超时或图片无可读文字时，沿用原有视觉回复路径。识字材料只用于当前回合。

同一回合可读取合并转发里的 QQ 图片。直接附图优先，转发节选会标出对应的图片编号，两种来源合计最多两张。转发图片过期或读取失败时，大肥鱼仍可依据能读到的转发文字回答，并说明图片状态。

已启用语音转写的群和好友私聊也能读合并转发里的语音。每轮只转写已展开内容中最新的一条，结果同文字节选一起用于本轮回复。原始消息归档沿用配文或转发标记。语音失效、超出转写能力或未开启转写时，仍可按能读到的文字和图片回答。

```json
{
  "roleExpressions": {
    "ohjingjing.dafeiyu": [
      { "id": "smile", "label": "轻松地笑一下", "emoji": "🙂", "qqFace": 14 }
    ]
  }
}
```

表情与最后一条文字一起发送。网关明确拒绝表情时可退回备用表情，回执丢失时记录待核对。分段、表情以及暂停已通过模拟网关联调。测试服务已运行包含这些功能的发布包，实际 QQ 客户端的表情显示待联调。

### QQ 定时群提醒

在运营后台输入管理员令牌并刷新，打开「定时群提醒」，选择已启用回复的群。可设置一次性、每天或每周的提醒。按所选时区填写时间，设置独立的计划静默时段和 1 至 120 分钟的有效发送窗口。列表按计划时区显示下次执行时间。每条计划可单独暂停、恢复或取消。固定正文直接发送，无需调用模型。

0.1.29 起可在新建计划时勾选「用本群的模型润色正文」。运行时将预设正文和角色的群聊表达设置交给本群模型，用量单列为「定时群提醒润色」，纳入后台预算。关键时间、数字和英文编号的校验失败，或预算不足、模型不可用、正文含链接等受保护字段时，仍在有效窗口内发送原文。生成中暂停、取消、失去群权限或超过窗口，则跳过该轮。最近投递可展开查看提交给网关的正文，并查看本轮用了润色还是原文。

发送前核对当前登录账号、群回复权限、渠道状态、群静默和计划静默。同一群的提醒至少间隔一分钟。超过窗口的轮次跳过，重复计划保留下一次执行时间。最近投递列表显示已发送、失败、超时或待核对。取消保留已有回执。服务重启后核对发送记录，无法确认的一轮留待核对。

### QQ 群内主人命令

在服务端配置 `channel.ownerId` 为操作人的 QQ 号字符串并重启后，该账号可在已启用回复的群里 @ 机器人并发送 `/机器人 暂停`、`/机器人 恢复` 或 `/机器人 状态`。命令使用网关报告的发送者账号核验，其他成员发出的命令会被忽略。

群内命令和运营后台操作共用同一个暂停状态。暂停立即取消排队及正在生成的直接回复和主动发言，已交给网关的消息按回执核对。恢复后仅处理新触发的回复。已启用的群观察和摘要继续运行。命令及其确认消息不写入模型聊天上下文或摘要。关闭 IM 渠道或设置全局暂停时，群内命令不可用。权限、重复事件去重及快速暂停后恢复已通过模拟网关验证。测试服务已部署该功能，待配置主人账号后验收真实群内操作。

### QQ 好友私聊

运营后台的「QQ 私聊」可以添加获准联系人。联系人以 QQ 好友文字会话发起后，机器人使用服务端配置的模型和默认角色回复。上下文按机器人账号与联系人分别保存，群聊、桌宠个人聊天和群友画像使用各自的作用域。

在好友私聊中可以引用自己或机器人之前发出的文字，再输入「展开这一句」之类的问题。服务优先使用当前账号、联系人和角色在保留期内的这条引文。引用机器人回复时，会通过已确认的 QQ 回执一并定位当时的原问题。升级前尚未登记引用编号的消息、已过期的消息和撤权清理的内容会提示无法读取，可直接贴出需要讨论的文字。

### QQ 私聊定时提醒

在「QQ 私聊」为联系人选择「开放定时提醒」。联系人从自己的 QQ 好友私聊发送 `/提醒订阅`，然后创建提醒。提醒默认按北京时间安排。订阅时可填写时区，例如 `/提醒订阅 America/New_York`。

| 私聊命令 | 用途 |
| --- | --- |
| `/提醒 30分钟 喝水` | 创建一次相对时间提醒。支持分钟、小时和天，每天按 24 小时计算。 |
| `/提醒 YYYY-MM-DD HH:mm 正文` | 按当前订阅时区设置日期和时间。切换时区后，已创建提醒沿用原来的执行时刻。 |
| `/提醒 每天 09:00 喝水`、`/提醒 每周三 20:00 备份` | 创建按天或按周重复的提醒，以创建时的时区和当地时间运行。 |
| `/提醒列表`、`/提醒取消 编号` | 查看或取消自己的提醒。取消重复计划时填写完整编号，例如 `R1`。 |
| `/提醒勿扰 23:00 08:00`、`/提醒勿扰 关闭` | 设置跨午夜或当天的静默时段。新订阅默认在 23:00 至 08:00 延后提醒。 |
| `/提醒暂停`、`/提醒恢复` | 暂停或恢复，未过期的计划保留。 |
| `/提醒退订` | 撤销接收授权并取消待发送提醒。 |

正文最多 120 字，按原文发送。每位联系人的待发一次性提醒与有效重复计划合计最多 10 条，按订阅时区每日最多尝试发送 4 次，两次尝试至少间隔一分钟。静默、暂停或 QQ 离线时延后。一次性提醒从原时间起保留 24 小时，重复提醒的每一轮保留 2 小时，过期的轮次直接跳过。暂停和恢复沿用原计划，退订会取消全部待发提醒和重复计划。

重复计划按创建时区运行，夏令时切换后仍按指定的当地时间安排。跳过当地时间不存在或重复出现的轮次。到点重新核对当前 QQ 登录和接收授权，每轮独立记录投递结果。网关回执不明确时保留待核对结果，后续轮次按原计划推进。运营后台可查看时间、状态和可用的回执编号，提醒正文仅用于联系人指令和投递。

### QQ 私聊角色问候

在「QQ 私聊」为联系人选择「开放角色问候」。联系人从自己的好友私聊发送 `/问候订阅 18:30 Asia/Shanghai` 设置时间和时区。可用 `/问候状态` 查看安排，用 `/问候暂停`、`/问候恢复` 或 `/问候退订` 管理订阅。用 `/问候勿扰 23:00 08:00` 设置静默时段，或用 `/问候勿扰 关闭` 关闭静默时段。角色问候和定时提醒分别授权和订阅。

问候默认每天最多尝试一次。连续发起两次发送尝试且联系人未接话时，改为每三天。连续四次后改为每七天。联系人发来普通私聊后恢复原节奏，并在两小时内优先处理当前会话。每轮保留两小时，超期跳过。发送前复核账号、订阅、静默时段和当前角色。模型调用只使用角色表达设定与联系人本地时段，计入服务端后台预算的「QQ 私聊问候」。运营后台可查看时段、降频状态和发送回执。网关回执不明确时保留待核对记录。

后台显示私聊发送回执与独立的模型用量。模型故障时发送简短应答，网关回执中断时记录待核对。撤销联系人会取消尚在生成的回复，并清除其本地会话和相处状态。历史按 `messageRetentionDays` 保留。群临时会话和主动私聊后续单独验收。

0.1.47 用隔离实例创建临时订阅和计划，向获准的测试联系人各投递一条定时提醒和角色问候。两条消息均从真实 QQ 好友会话读回并核对平台消息编号。测试结束后清理隔离实例，并恢复线上私聊功能授权。

### QQ 账号资料与空间

运营后台的「QQ 账号资料与空间」可以核对当前登录，分别开启昵称、头像、个性签名和空间文字动态，并为已管理的群单独开启机器人自己的群名片。各操作共用账号的最短间隔，支持立即提交与预约。昵称、签名和群名片提交后用免缓存查询核对，群名片还会在写入前核对群成员身份。PNG 头像收到网关回执后显示待读回，可以在 QQ 客户端核对生效情况。

空间评论和点赞使用各自的权限开关。填写获准互动的空间所属账号后，可选择其近期动态或填写动态编号。写入前会核对登录账号、目标权限和动态是否可读。评论尽量读回，点赞和取消点赞保存平台接收回执。操作记录保留目标与结果，同一操作编号重试时返回已有回执。

空间文字发布按账号选择仅自己、好友或所有人。发布回执中的动态编号用于读回该条动态。后台记录请求范围和读回结果，可见范围是否实际生效由 QQ 客户端验收。账号操作具有独立的编号和历史回执。同编号只处理一次，断线或服务重启时结果不确定的操作留作核对。日志保留操作摘要、范围和状态。空间能力查询位于「插件中心 → IM 渠道」。

填写「执行时间」后，昵称、头像和文字动态按钮会切换为预约。时间使用浏览器所在设备的时区，可填写最晚执行时间。已保存的预约可预览和撤销。服务端到点执行并再次核对登录账号、权限、空间范围和最短间隔。离线、操作间隔未到或权限暂停时，待执行预约留在队列。超出截止时间后结束预约。已进入网关调用的动作使用原编号记录结果，中断时留作核对。

勾选「到预约时间由角色生成文案」，在输入框填写允许发布的角色近况，再选择「预约生成并发布」。当前实例的默认角色决定表达风格，近况素材用于文案内容。生成调用沿用摘要模型路由、备用档案和后台预算，用量单列为「空间文案」。预算不足时预约等待额度恢复。模型跳过或生成失败时结束该预约。已经保存的文案可随预约恢复，提交时继续核对账号许可、可见范围及截止时间。

「角色日记与重复发布」可按当前默认角色保存近况。勾选「允许用于空间动态」的条目才会参与选题。每个 QQ 账号可启用一条重复计划，设置下次执行时间、天数间隔、可执行窗口和与账号权限一致的可见范围。每轮按顺序选一条尚未选题的日记，沿用生成式预约的预算和投递规则。服务恢复时只处理仍开放的窗口。暂停计划、撤下素材或切换角色后，尚未提交网关的关联预约会结束。

在「角色日记与重复发布 → 自动撰写日记」可登记允许提交给摘要模型的角色事件。自动撰写和两类自动收录默认关闭。启用后，可选收录默认角色变更、已读回的 QQ 昵称更新和已收到回执的头像更新。模型接收脱敏的事件和角色表达设定，使用摘要路由与后台预算，用量记为「角色日记」。

生成的日记默认私有。空间计划需要在条目上开启独立的发布许可。撤回事件会清除事件正文、中止进行中的撰写，并收回关联日记的发布许可。已生成的私有日记仍可编辑或删除。暂停撰写会保留待处理事件，已经开始的生成在中断后结束。

默认在 `http://127.0.0.1:8789` 打开管理员页面。实际收到授权群的消息后，可以查看群标识、配置画像、为核验身份的桌宠用户发放订阅令牌。远程桌宠使用经 HTTPS 反向代理发布的地址，并使用订阅令牌。服务端进程应由部署方配置常驻与重启。用户桌宠退出不影响群聊进程。

运营者在「桌宠订阅」填写核验后的 QQ 标识，可勾选多个已收到消息的观察群。本人私有记忆的拉取和上传分别授权。新令牌只在发放结果中显示，可手动隐藏。订阅列表显示 QQ 标识、授权群和记忆权限，可按行撤销。撤销后，持有旧令牌的桌宠会在下次读取时收到失效提示。

Windows 测试服务的现有计划任务由 Windows 用户登录触发，无运行时限，失败后按一分钟间隔最多重试三次。已核对服务健康，真实 QQ 网关当前在交互式 Windows 会话运行。测试机整机重启后的 QQ 登录恢复、持续运行时间与实际投递仍需联调。

订阅接口提供本人画像、授权群和近期摘要。在主窗口「群动态 → 群成员画像」点击「拉取群友画像」，即可按群内称呼筛选已发布的成员。也可按 QQ 标识单独查询。首次拉取由用户触发，此后在当前群页面每 30 秒更新。停止刷新会清除本次拉取的目录，切换群会清除原群的目录和讲解。同一群的订阅者读取相同的发布版本。

在「工作区」筛选来源和会话后，使用「查看已发布画像」读取该服务发布的群画像和群友画像。同名群按服务连接区分。更换订阅身份会清除该连接的旧数据和关注记录。多个会话同时产生摘要时，桌宠显示一条合并提醒，打开后可逐条跳回对应的工作区会话。

每个工作区会记住上次手动选择的来源。提醒跳转临时显示目标会话，切换工作区时恢复已保存的来源。使用「配置工作区 → 桌宠摘要提醒」可单独设置暂停、勿扰时段和提醒间隔。默认沿用全局勿扰时段。全局暂停以及全屏、演示和锁屏保护适用于所有工作区。同一工作区在冷却或勿扰期间新增的摘要会合并，恢复后提醒每个已关注会话的最新摘要。

点击「讲讲这位群友」后，确认页显示使用的个人模型和接口主机。运行时在发送前核对订阅、画像和跟随角色的版本，只使用这位群友当前已发布的称呼与简介。生成结束后再次核对，画像已撤下或访问权限变化时丢弃结果。讲解显示在该画像卡片下，计入个人模型用量，个人聊天历史独立保存。

主窗口的「群动态」和悬浮桌宠的「群摘要」都可点击「讲给我听」。确认页显示个人模型及接口主机。运行时只使用当前群已发布的摘要和话题，发送前及生成后分别核对订阅、摘要版本和已跟随角色的版本。本人画像需在隐私设置中允许，并在本次讲解中单独勾选。讲解计入个人模型用量，显示在对应摘要下。切换群后会清除原讲解，个人对话历史独立保存。

群回复和摘要由服务端自有的模型配置执行，桌宠离线期间继续运行。每个群的摘要在独立的后台任务中生成，群回复可以同时处理。服务端可使用云模型和对应 Key，也可连接无需 Key 的本地模型。可选配置 `summaryModel` 单独指定摘要模型，字段与 `model` 一致，密钥通过进程环境变量 `OHJINGJING_SUMMARY_MODEL_KEY` 提供。省略该档案时，摘要沿用回复模型及其 Key。后台用量按回复与摘要分别统计。

摘要的模型等待时间默认 60 秒，可用 `summaryTimeoutSeconds` 调整。摘要失败后会保留当前消息批次，并按失败原因逐步延后重试，延迟最多 15 分钟。退出或重启后继续遵守已保存的重试时间。新的消息进入下一批。运营后台群列表显示失败原因、尝试次数和下次重试时间，也可手动重试。手动重试继续受模型预算和群摘要策略约束。

### 后台任务

运营后台的「后台任务」可按群和类型筛选群摘要、画像候选及主动聊天。页面显示最近 50 条，进行中的任务排在前面。每次开始生成都会保存触发原因、资料来源类别、模型用量、结束状态及对应的摘要、画像候选或发送回执。生成中的任务提供「取消本次生成」入口。任务记录按群聊原文保留期限清理，最长保留七天，从使用本功能后的新任务开始记录。

### QQ 独立收件

需要在服务器切换期间保留 QQ 收件时，可以运行独立收件进程。以 `qq-ingress.example.json` 为模板重新保存配置，填写实际账号、网关以及主服务初始已授权的群。`policyDatabase` 指向同一台机器上主服务的数据库，收件进程只读当前群策略和私聊授权，消息缓冲使用独立的 `database`。缓冲最多保留最近 24 小时和 20,000 条。

使用 `windows-service-task.ps1 -Ingress -Config <收件配置> -StateDirectory <收件状态目录>` 以独立任务启动。主服务把 `qqIngress` 设为同一台机器的回环地址及端口，两端在各自的 Windows 凭据配置中填写同一个独立收件令牌。接收端口仅监听回环地址。运营后台的 QQ 网关检查可查看收件连接、交接和积压状态。

发布器设置 `requireIngress` 后会等待当前入站处理结束再切换主服务。独立进程持续收件，新进程从保存的游标接续，回复继续使用原渠道的发送回执和去重规则。

启用 `recoverHistory` 后，网关重连或收件进程恢复时，可从最近 24 小时内的检查点补收已授权会话。群消息按原策略归档。私聊仅补收同一账号和联系人在授权期间的记录，普通文字可参与后续对话。历史消息按平台时间归档和去重，历史命令与旧回复不会重新执行。

达到单批页面或读取时限后，独立收件保存该会话的续读位置，下一批从那里继续。网关再次断开时，从最新页面重查，直到覆盖原来的检查点。网关连续返回同一位置时，收件器保留待补记录。

### 群聊回复追踪

用管理员令牌进入运营后台后，可在「群聊回复追踪」按群、触发方式或消息编号查询最近 50 条记录。明确 @、点名或引用机器人时可看到回复、暂停或策略中断情况。自然接话、连续追问和主动开场会记录触发、结果及实际发生的模型请求，同时抽样保留静默时段、冷却、近期发言、重复话题和预算等前置拦截原因。同群、同触发方式和原因最多每五分钟记录一次，同一事件的同一原因去重。前置拦截不占用模型预算，也不计入回复触发率。

群友引用机器人分段回复时，运行时用发送回执定位同群原问题，以及同一轮另一条已确认发送的回复。服务重启后可从保留期内的记录补回上下文。原问题只从近期上下文或当前群允许保留的原文中读取。只有已发送的分段才会补入上下文。

当前消息明确提议调整日期、前文只有一个可追溯的时间时，回复发送前会确认是否沿用原定时间。已经确认的变更和多个备选时间继续按普通对话处理。

每条追踪显示角色版本、实际供应商模型、模型用量和每段回执。回复正文、原消息和提示词仍由各自原有的权限和数据策略管理。网关断线导致的未知结果标为「待核对」，分段回复可区分已发送和未尝试的部分。记录从部署后积累，按群原文保留期清理，最长七天。群订阅令牌仅可访问授权群数据。

### 群聊统计

在运营后台选择「群聊统计」，也可以从「群聊策略」中点「查看统计」。支持近 24 小时和近 7 天，按北京时间汇总各小时的入站事件、已观测到的发言账号和实际发送回执。发言账号按网关事件去重，显示的是观测到的账号数。页面列出统计窗口和实际记录的起止时间。服务离线、渠道停用或本群同时停用观察和回复时可能存在观测空缺。

「QQ 网关观测覆盖」按本服务实例显示在线、断线或连接中、渠道停用以及缺少观测的时长。服务记录连接状态变化，并每 10 秒补记一次观测。首次启动监测前、进程重启间隔及采样停顿显示为「缺少观测」。群消息量沿用实际接收的事件。桌宠主窗口和悬浮窗对已授权群可查看近 24 小时覆盖，阅览摘要仍按原有授权。

「按触发方式看回复」按处理轮次统计 @、点名、引用、连续追问、自然接话和开场。分段回复收到全部回执才计入完整送达。收到部分回执且剩余各段已结束时计入部分送达，仍有发送中或结果未知的回执计入待定。点触发方式可打开本群最近的对应追踪。冷却、静默等前置拦截单列，并沿用五分钟抽样。样本数用于对照记录，实际误接话需结合会话语境判断。

「本群模型用量与估算费用」使用同一个时间窗口，按模型和用途列出实际调用次数、Token 和估算费用。费用按币种分别合计，未计价请求单列。归属以机器人账号和群号共同判定，重试和备用模型调用各按实际请求计量。这项数据仅供管理员查询已管理的群。

管理员可在「运行状态与模型用量」导出所选时段的总用量，也可在「群聊统计」导出所选群和时段。CSV 包含范围、UTC 时间、模型、用途、请求结果计数、Token 与分币种估算费用，缺失用量保留为空。最近 20 次导出可在「最近的用量导出」查看，记录操作角色、时间、范围和导出行数。

在「运行状态与模型用量」可组合选择模型、用途和档案当前凭据。总用量、成功率、P95、群级模型用量和对应 CSV 使用同一组筛选。群活动和投递统计使用群与时段。选择「全部凭据版本」时，按模型或用途也可查询轮换前及未关联档案的历史请求。CSV 和导出记录保留所选筛选条件。

回复触发率的分母是新版在回复已开启、未暂停且网关在线时收到并去重的普通群消息。主人命令和网关标记的机器人消息不纳入样本。分子是其中实际进入直接回复、连续追问或自然接话流程的消息数，同一条消息最多计一次。独立开场单独计入发送回执。旧版已接收的事件仍用于活动统计，从新版开始记录触发率样本，样本最多保留七天。无样本时显示「暂无样本」。

取消摘要会保留原批次，并按既有策略等待重试。群列表可按需关闭摘要或提前重试。取消画像产生的这次请求仍记入模型用量，画像候选不会生成。主动聊天进入投递后，页面继续显示回执状态。服务重启后会沿用已保存回执，对结果未知的发送保留待核对记录。任务列表包含运行元数据，正文和画像证据仍在各自的运营页面查看。

桌宠通过服务地址和订阅令牌读取已发布的群摘要、近期历史和授权画像。个人聊天、悬浮桌宠对话及模型讲解使用个人模型的 API Key。使用这些模型功能前，用户需要在桌宠的「个人模型与 API Key」里配置密钥。

在「设置 → 群动态订阅」可以保存多个有名称的连接。旧版保存的服务会出现在列表中。新增连接时填写服务地址和该服务的订阅令牌。切回已保存的连接时，从 Windows 凭据库读取该连接的令牌。选择「未连接」时可继续使用个人聊天、本地待办和本机记忆。

摘要关注列表按连接保存。切换时，主窗口和悬浮窗清除旧连接的群动态、待展示摘要、跟随角色和云端记忆预览。切换后重新核对同步账号并按需启用上传或拉取。替换连接的订阅令牌会重置该连接的群摘要关注列表。已下载为本机记忆的记录可继续使用。

服务端可选配 `groupModels`，以群号为键、模型档案为值，覆盖该群的回复模型。专用密钥用进程环境变量 `OHJINGJING_GROUP_MODEL_KEYS` 的 JSON 对象提供，值按群号读取。启用专用档案的群必须已允许回复。后台用量按档案分开，专用模型余额可通过 `/admin/balance?group=群号` 查询。

### 服务端主备模型

在 `backupModels` 下按主档案位置填写完整的备用模型档案。`default` 对应默认模型，`summary` 对应已配置的独立摘要模型，`group:<群号>` 对应已配置的群专用模型，`profile:<档案标识>` 对应已配置的共享档案。用途沿用主档案，包括群回复、好友私聊、主动聊天、摘要和画像。备用密钥通过 `OHJINGJING_BACKUP_MODEL_KEYS` 提供，格式与位置一致，例如 `{"default":"备用档案的 Key"}`。有单独存放的备用 Key 时，启动脚本可按提示接收此 JSON。

主模型遇到连接中断、超时、HTTP 402、408、429、5xx、无法解析的接口响应或空结果时，每轮最多尝试一次已配置的备用模型。启用后两次调用共享该轮原有的等待上限。备用供应商会收到同一轮任务上下文。管理员取消、预算限制、鉴权失败或模型明确拒绝时，运行时结束相应处理。已有的群回复简短应答、主动聊天保持沉默和摘要批次重试仍按各自规则执行。

运营后台的「模型与 API Key」会分别列出主档案和备用档案。每次实际发出的请求独立记录用量，并按各自币种检查预算。「群聊回复追踪」和「后台任务」可按次查看模型和结果。单独测试模型档案时只调用所选档案。

### 运营后台切换模型路由

DSH 可在服务配置的 `dshTurns.purposes` 中按用途试运行，可选群回复 `reply`、好友私聊 `private`、摘要 `summary`、画像 `profile` 和主动聊天 `proactive`。`dshTurns.groups` 可把群场景限制在指定群。0.1.63 起可在 `dshTurns.privateContacts` 指定 `accountId` 与 `userId` 组合，用于从已授权好友中选取私聊灰度范围。空数组表示私聊全部沿用原运行时。运营后台的模型尝试记录会显示试运行使用的运行时。带图回复继续走现行视觉通道。

灰度群的摘要校验正文和话题结构，画像候选校验证据。遇到无效格式或空响应时，按当前路由最多再尝试一次，沿用总时限和后台预算。有备用模型时使用备用模型，只有主模型时可改用原运行时完成结构化任务。灰度画像使用摘要任务时限。达到输出上限时保留已用 Token，运营后台分别展示每次尝试的状态和用量。待审画像沿用发布流程。

`proactive` 灰度覆盖自然接话、连续追问、空闲开场和后台试演。模型先返回发言、表情或沉默的结构化决定，再校验发送权限、静默时段和内容时效。接话与开场沿用群的频率策略，决策时限为 15 秒。运营后台试演只使用输入的样本，生成记录可供查看。

试运行需准备兼容的 Node、DSH SDK 和 `dsh-text-turn.mjs`，通过 `OHJINGJING_DSH_NODE`、`OHJINGJING_DSH_SDK_ROOT`、`OHJINGJING_DSH_TURN_SCRIPT` 和 `OHJINGJING_DSH_STATE` 指定绝对路径。桌宠进程可以在 `OHJINGJING_DSH_DESKTOP` 中选择用途，例如将 `desktop` 用于日常聊天，或将 `summary-explanation` 用于摘要讲解。运行时初始化前失败会复用已取得的工具结果回退，已进入模型调用的失败按当前主备策略处理。

签名 Windows x64 试验包可通过 `scripts/build-desktop-release.ps1 -DesktopHarness` 内置运行时。构建前从项目目录执行 `npm ci --prefix dsh-runtime --ignore-scripts --omit=optional --omit=dev --no-audit --no-fund`。安装后在桌宠设置个人 Packy API Key，选用兼容的 DeepSeek Flash 模型即可进行本机对话和长对话续聊。角色、记忆及请求用量继续写入桌宠自己的数据目录，短期运行文件在每轮结束后清理。其他模型及群资料解读继续按现有路由运行。测试环境使用 `--fresh-install --packy-key-stdin` 可验收安装、真实模型、系统凭据、重开和取消。

Windows x64 服务端包提供 `dsh-runtime` 的版本锁。在解压目录打开 PowerShell，用已安装的 npm 准备依赖后，将以下环境变量设置到服务启动进程。安装使用包目录下的 npm 缓存并保留原生图像依赖，服务通过锁定的 Node 24 启动文本和视觉回合。

```powershell
$packageRoot = (Get-Location).Path
$sdkRoot = Join-Path $packageRoot 'dsh-runtime'
$scratch = Join-Path $sdkRoot 'tmp'
New-Item -ItemType Directory -Path $scratch -Force | Out-Null
$env:TEMP = $scratch
$env:TMP = $scratch
$env:NPM_CONFIG_CACHE = Join-Path $sdkRoot 'npm-cache'
npm ci --prefix $sdkRoot --ignore-scripts --include=optional --omit=dev --no-audit --no-fund
if ($LASTEXITCODE -ne 0) { throw 'DSH 运行时依赖安装失败。' }
$env:OHJINGJING_DSH_SDK_ROOT = $sdkRoot
$env:OHJINGJING_DSH_NODE = Join-Path $sdkRoot 'node_modules/node-win-x64/bin/node.exe'
$env:OHJINGJING_DSH_TURN_SCRIPT = Join-Path $packageRoot 'dsh-text-turn.mjs'
$env:OHJINGJING_DSH_STATE = Join-Path $sdkRoot 'turns'
```

在「模型路由」选择默认对话、摘要与画像或某个已管理的群，再选择档案并点击「应用档案」。可以在 `modelProfiles` 下按自定标识预配置共享档案，档案结构与 `model` 相同。共享档案的 Key 通过 `OHJINGJING_MODEL_PROFILE_KEYS` 提供，JSON 的键是共享档案标识。群专用档案保持所属群的使用范围。默认路由也服务于沿用默认配置的群、私聊及摘要。

群聊看图可在 `groupVisionProfiles` 中按群选用一个已设置 `vision: true` 的共享档案。后台「模型路由」显示该群的看图档案。被 @ 或收到相关追问时，服务端读取本轮能取得的图片与表情包附件，交给看图档案分析。普通回复及摘要继续使用各自的模型路由。普通 Unicode emoji 作为文字处理，QQ 原生表情保留编号。

启用 Harness 的群聊和获准私聊会把本轮的图片按原顺序连同角色上下文交给支持视觉的模型。OCR 结果仍按图号补充。本轮处理文件随模型回合清理。现有 Windows 安装若缺少原生图像组件，本轮沿用原看图路径，图片仍随模型请求提交。

可以用自然语言同时要求看图和核对公开资料，需要在配文中写出公开检索词或链接。网页查询只使用配文中的公开文字。公开资料不足时，回复仍保留能从图中确认的部分。

切换从下一轮开始生效，进行中的模型调用及其备用尝试沿用本轮配置。用量仍按实际调用的档案记账。页面显示当前版本及最近 30 次变更，可回退到历史选择或恢复当前启动配置。回退发生变更时会保存为新版本。两人同时编辑时，旧版本的修改会被拒绝。档案被移除、缺少 Key 或更换接口后，旧选择会被标为不可用并沿用配置，管理员可选取当前可用档案。路由历史统一将操作人记为管理员，并保存时间。凭据由启动环境管理。

「测试生效路由」使用一条固定测试句验证当前路由，沿用主备切换规则。测试结果显示每次实际调用的请求编号、状态、用量与估算费用。调用计入「模型连接测试」，测试完成后继续使用现有路由版本。

### 模型预算与告警

运营后台的「模型预算」显示今日和本月的实际请求计数、已计价估算费用、剩余以及未计价请求数。日、月按北京时间重置，成本按原币种统计。填写每个币种的费用上限后，可设置告警百分比，并选择是否在达到上限后暂停该币种的后台调用。已发出的请求在返回用量后计入费用，仍可能产生后续费用。供应商余额和额度继续通过各模型余额入口查询。

后台每日和每月请求上限对摘要、画像候选、自动接话与开场、空间文案及角色日记生效。调用开始时计数，进行中、失败和结果未知的请求也会占用次数。费用缺失时照样可以按请求次数控制后台使用。限额留空表示不限，设置为 `0` 可暂停对应预算范围的后台调用。QQ群 @ 和获准好友私聊继续按各自策略响应。预算保存到服务数据库，重启后继续生效。状态及设置通过 `GET /admin/budget` 与 `PUT /admin/budget` 提供给管理员。

「模型与 API Key」列出默认、独立摘要及群专用档案，显示各自用途、供应商、凭据配置状态、最后使用时间、请求次数、Token 和估算费用。点击「查询额度」使用该档案的服务端 Key，点击「测试连接」会发起一条短请求并计入用量。档案的 `billing` 支持 `deepseek`、`openrouter`、`packy` 和 `none`。未单独配置摘要模型时，默认档案也承担摘要和画像任务。

在「供应商余额与 API Key 额度」点击「查询全部额度」，可以一起查看默认、摘要、群专用及备用档案。相同供应商的同一个 Key 归在一起。DeepSeek 不同 Key 属于同一账单账户时，为对应档案填写同一个 `billingAccount`。未标记的账户按 Key 独立展示，标签冲突会在概览中提示。OpenRouter 和 Packy 按 Key 显示各自的额度。

余额快照记录币种、来源和查询时间，服务端重启后仍可读取。快照超过 15 分钟时标记为过期，供应商查询失败时会同时显示上次成功的快照。轮换 Key 后，新 Key 从未查询状态开始。查询额度与模型请求用量分别记录。

档案用量按当前档案和凭据版本统计。上线前的请求、已轮换凭据的用量均可从「运行状态与模型用量」查看。管理员令牌参与凭据版本的校验，轮换它会开启新的档案统计版本。模型配置和 Key 通过服务进程配置更新。

「运行状态与模型用量」按所选时间范围显示模型请求成功率、成功次数、样本数和 P95 耗时。样本包括已成功、已失败及已返回空响应的请求。P95 取耗时从短到长排列后达到 95% 的第一个样本，单位为毫秒。暂无已确认结果时，页面显示暂无样本。

### 群聊与群友画像

在运营后台刷新状态后，打开「群聊与人物画像」并选择已观察的群。「查找群友」可按最新群内称呼、已发布称呼、QQ 标识或后台标签查询。成员列表显示最近发言时间、保留期内的归档样本数、是否已发布及候选是否待审阅。点击「查看画像」可直接载入该成员。后台标签按群保存，仅在运营页面可见。

对象填 `group` 可查看群画像，也可手动填写群友的 QQ 标识。生成候选前需开启群摘要。群画像至少需要八条发言和三位发言者，群友画像至少需要该成员的四条发言。候选只使用同群保留期内的发言，提示模型仅归纳公共话题、可观察行为和明确表达的非敏感偏好。素材中的链接、邮箱、常见凭据和长数字会被遮盖。

运营者可查看候选引用的片段和时间，修正公开称呼与简介后发布，也可以驳回或撤下。启用「允许作为群聊回复的参考」后，群回复可以使用对应群的群画像和当前发言者画像。桌宠订阅只提供已发布版本，候选与证据仅向运营后台提供。证据删除或过期后，基于该证据发布的画像停止共享。本人画像沿用手工管理，私有记忆不参与候选生成。画像候选沿用摘要模型配置，运营后台用量单列为「画像候选」。

### 开发任务与隔离发布

开发任务可在服务端设置 `development.target`、`development.maintainers` 和独立的 `development.database`。维护者需同时获得对应 QQ 私聊权限。开发执行进程用 `OHJINGJING_DEVELOPMENT_DATABASE` 打开队列的绝对路径，并用相同的目标标识选择隔离发布实例。管理员可通过 `GET /admin/development` 查看队列是否独立、执行进程状态和最近发布版本。

开发运行时遇到影响目标行为的关键信息缺口，会让原任务进入「等待补充」。维护者可直接引用原 QQ 私聊里的追问，用文字回复。也可发 `/开发补充 任务号 内容` 或用桌宠任务面板补充。引用会按同一私聊的 QQ 送达回执核对，只接受当前等待补充的版本。补充保留任务号、原消息来源、需求与验收条件，再由隔离执行进程继续。单次最多 1000 字，合并后需求不超过 2000 字。等待期间暂停该任务的测试和发布，维护者也可在桌宠取消。旧版桌宠仍可查询任务。

候选验收失败后的单轮修复与诊断能力见[当前验收进度](OHJingJing-机器人平台设计方案.md#当前交付状态)。

### 语音转写与角色声线

入站语音默认关闭。需要启用时，在服务端配置中填写 `qqVoice.endpoint`、`model`、`hasKey`、`groups` 和 `privateContacts`，可选 `language`。端点应接收包含 WAV 文件和模型名称的 multipart 请求，并返回带 `text` 字段的 JSON。需要凭据时，由启动环境或 Windows 服务凭据提供 `OHJINGJING_QQ_VOICE_KEY`。语音授权范围和原有群回复、好友权限均须满足。

`qq.milky` 候选渠道在授权后复核原消息、发送者和会话，仅从指定的 QQ HTTPS 媒体地址取回语音。SILK 解码为 PCM WAV，已有 PCM WAV 直接校验，超过 60 秒的输入不进入转写。转写使用实例配置的现有路径，独立收件缓冲只保存消息状态及正文，不保存语音下载地址。

语音条回复通过 `qqSpeech` 独立启用。获准的好友私聊可发送 `/语音` 加问题，也可说「用语音讲个冷笑话」或「讲个冷笑话，语音的」。群里可以 @ 或点名机器人。转写和合成的用量在后台分别显示。

群聊与私聊可按各自授权范围配置同一角色声线。Harness 根据当前发言选择语音或文字和语气预设。明确请求语音且未指定篇幅时，优先生成上限内的完整口述正文。超出上限或合成失败时保留正文，以文字投递。群聊回复追踪会展示原因。

私聊可单独配置 `qqPrivateSpeech`，沿用 `qqSpeech` 的字段格式，`groups` 填空数组，`privateContacts` 填获准联系人。如端点需要凭据，使用 `OHJINGJING_QQ_PRIVATE_SPEECH_KEY`。省略 `qqPrivateSpeech` 时继续使用 `qqSpeech` 的私聊配置，设为 `null` 时关闭私聊语音。

可按端点配置 `maxCharacters`，默认 220。Harness 会按上限组织适合口述的完整正文。超出上限的回复按原文发送文字。

普通说法由 Harness 结合本轮语义和可用能力选择文字或语音。角色包的 `speech.voice` 是固定声线标识，`speech.direction` 是表演方向。兼容表演指令的 HTTP 合成端点可设 `qqSpeech.style: "instructions"`，并在 `roleVoices` 中把角色的声线标识映射到端点音色，例如为大肥鱼绑定 `dafeiyu`。HTTP 端点也可为同一音色注册多个表演预设，例如 `"dafeiyu": { "voice": "fish-neutral", "styles": { "playful": "fish-playful", "warm": "fish-warm" } }`。未配置的语气使用该角色默认音色。已声明专属声线的角色在缺少兼容音色时使用文字。

- Windows 本机合成填写 `engine: "windows"`、`voice`、`groups` 和 `privateContacts`。音色可用已安装名称或语言区域，例如 `zh-CN`。本机合成在进程内存中生成 WAV，记录次数和耗时，供应商费用为零。
- HTTP 合成填写 `endpoint`、`model`、`hasKey`、`voice`、`groups` 和 `privateContacts`。端点接收 `model`、`input`、`voice` 和 `response_format: "wav"`，返回 PCM WAV。可选 `timeoutMs` 默认 8000，支持 1000 至 25000 毫秒。需要凭据时由启动环境或 Windows 服务凭据提供 `OHJINGJING_QQ_SPEECH_KEY`。两个引擎均可用 `roleVoices` 指定角色音色。

### Windows 开机运行单实例

用长期开启群聊服务的 Windows 账户打开管理员 PowerShell，在解压的服务目录执行以下命令。该账户须能读取程序及配置，并写入 SQLite 数据目录。程序和配置的写权限限于可信部署人员。已有实例迁移时先停止原启动方式，再使用同一份配置与数据。状态目录用于任务凭据和最近一次启动的日志，首次登记时指定一个新目录。

```powershell
.\windows-service-task.ps1 -Config .\server.config.json -StateDirectory .\task-state
```

按提示输入该 Windows 账户的密码，以及配置所需的管理员令牌、网关令牌和模型 Key。也可以沿用当前 PowerShell 进程中已经设置的服务端凭据。脚本将服务凭据按本机 Windows 账户加密保存，计划任务只携带文件路径。系统或账号变更后需重新登记并保存凭据。 [Windows 凭据加密说明](https://learn.microsoft.com/powershell/module/microsoft.powershell.utility/export-clixml?view=powershell-5.1)

脚本登记「OHJingJing Group Service」开机任务并立即尝试启动。任务可在 Windows 登录前运行。群聊进程退出后，启动脚本间隔五秒尝试重启，并写入 `task-state\task.log`。群聊进程连续十次运行不足一分钟即退出时，启动脚本结束并记录错误。Windows 计划任务对启动脚本配置了每分钟一次、最多十次的异常重试。

服务可在网关离线期间响应健康检查和运营后台，QQ 通道会持续重连。网关进程的开机启动及 QQ 登录由网关本身负责。检查任务状态及 `task-state\server.error.log`，再打开运营后台核对 QQ 登录与账号匹配。

### 管理多个机器人实例

将 `instances.example.json` 复制为 `instances.json`，为每个条目从 `server.config.example.json` 建立一份独立服务配置。清单的 `config` 相对于清单目录，数据库路径相对于各自的服务配置。每个实例使用独立端口与 SQLite 文件，并在启用 QQ 渠道时填写不同的 `channel.expectedBotId`。启动管理进程后，每个 QQ 网关都会先核验实际登录账号。`start: false` 的实例可以从管理页按需启动。

管理页使用 `OHJINGJING_MANAGER_TOKEN`。实例凭据使用 `OHJINGJING_INSTANCE_<实例标识>_` 前缀，标识转为大写，连字符替换为下划线。例如 `first` 的管理员与模型变量是 `OHJINGJING_INSTANCE_FIRST_ADMIN_TOKEN` 和 `OHJINGJING_INSTANCE_FIRST_MODEL_KEY`。同样可按实例提供 `ONEBOT_TOKEN`、`SUMMARY_MODEL_KEY`、`GROUP_MODEL_KEYS`、`BACKUP_MODEL_KEYS` 和 `MODEL_PROFILE_KEYS`。各管理员令牌与管理页令牌分别设置，长度至少 24 位，可用字母、数字和 `_ . ~ -`。

```powershell
node .\instances.cjs .\instances.json --check
node .\instances.cjs .\instances.json
```

按启动提示打开本机管理页，输入管理令牌查看进程状态、启停或重启，也可以打开每个实例的运营后台。实例后台分别使用自己的管理员令牌，桌宠连接相应服务地址并使用该实例签发的订阅令牌。管理页只监听回环地址。显式停止持续至本次管理进程退出，异常退出会退避重启。修改实例列表或管理端口后，重启管理进程以重新校验。业务配置仍可通过各实例后台操作。

#### 发布和回滚实例配置

1. 编辑该实例在清单里指定的服务配置文件。模型和网关凭据继续用该实例的环境变量提供。
2. 在管理页点该实例的「配置版本」，刷新后点「发布磁盘上的配置」。管理器校验源文件指纹、当前版本和各实例端口、数据库、账号的隔离，并运行同一服务入口的启动预检。更换已启用的网关时核对登录账号、新配置的独立收件以及清单指定的 QQ 能力。只更换独立收件地址时也会核对其账号、协议和在线状态。
3. 运行中的实例会试启动新配置。在提交版本并打开收发前，新进程会重新核对本次调整的网关和独立收件。端口占用、登录账号变化或收件离线会恢复旧配置。已停止的实例可发布配置并保持停止。其他实例的进程继续运行。
4. 从版本列表选择「回滚到版本」。回滚产生一条新记录。再次打开管理器时继续使用生效的快照，磁盘配置仍可继续编辑和发布。

### 在线备份与恢复演练

服务端发布包内置 `service-data.cjs`。运行以下命令时，群聊服务可以继续工作。备份目录保存一份独立的 SQLite 数据库和校验清单。该数据库包括已有摘要、画像、订阅授权、用量和发送回执，应放在服务账号控制的存储中。

## 私有记忆同步

在「设置 → 当前角色的个人记忆」展开「从个人聊天提取记忆」，点击「提取记忆」。桌宠把最近最多 16 条尚未处理的本人发言发给当前个人模型，提取请求计入该档案的本机预算。候选附有可核对的原话，可编辑、采纳或忽略。每个角色单独保存候选、处理位置和自动采纳设置。

自动采纳默认关闭。开启后，只有本人原话可直接表示的常见日常偏好会自动写入本机记忆，例如「我喜欢喝茶」。其他候选继续由用户审核。已采纳的文字可编辑、删除和手动上传到本人私有空间。候选、引用原话和提取进度留在本机。

运营后台发放桌宠令牌时，分别勾选私有记忆的读取和写入权限。同一核验 QQ 身份可为不同设备领取权限不同的令牌。群友画像目录和私有记忆使用独立接口。

在桌宠设置中，上传和拉取默认关闭。开启后，按当前角色手动上传，或预览已获授权的服务端记忆并确认使用。更改服务连接或关闭拉取会清理此前确认的服务端记忆。两端同一条记忆有不同编辑时，可在预览中另作一条，再手动上传。若要删除服务端副本，需在预览中确认，版本校验成功后才删除。群画像、聊天原文和密钥只使用各自的存储和请求路径。

同时开启上传和拉取后，可以在预览里选择「下载为可编辑记忆」。桌宠会记录服务端版本，之后手动上传同一条记录。版本冲突时可选「本地版本另作一条」或「采用服务端版本」。下载的可编辑记忆及已采用的服务端版本只向原订阅上传。更换订阅后仍可在本地使用这些记忆。

服务请求确认订阅失效时，主窗口和悬浮桌宠会清除已显示的群资料，运行时会清除只读记忆缓存、跟随的群角色和摘要通知游标。仅撤销记忆读取权限时，会清除已确认的只读缓存，上传权限按独立设置处理。本机保存的可编辑记忆在断线或撤权后仍可使用。
