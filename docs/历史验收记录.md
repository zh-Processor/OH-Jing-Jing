## 设计阶段的里程碑

本轮已在 Windows 隔离目录用真实 Packy 模型完成 DSH SDK 握手、文件工具调用和用量读回。独立测试核对了取消、超时后未完成的模型连接会关闭。文本回合的测试核对了角色和上轮上下文保留、用量读回及普通对话的工具范围。已通过 SSH 核对真实调试群的 QQ 登录、观察与回复状态。查询的 43 条追踪中确认了 23 次 @ 回复、1 次追问和 3 次自然接话或开场。新版搜索真实投递仍待补验。

多来源工作区已接入桌宠和订阅 API。自动化验证了两个来源并行更新、同名群隔离、单来源异常期间另一来源继续同步、应用重启按游标补拉，以及撤权后清除缓存。真实 QQ 服务的授权摘要已与第二个隔离服务的合成消息同时同步，隔离来源断开时仍可刷新真实摘要。服务端按群单独授权归档原文和从桌宠发送，模拟网关已核对账号匹配、目标群、平台回执与重试去重。QQ 私聊受理开发需求、工作区任务查询与提交已通过模拟网关联调，覆盖维护者校验、目标实例和重复请求。

0.1.27 在同一个 Windows 主窗口连接真实 QQ 服务和使用独立数据库的第二个测试服务。两个来源使用相同群名和会话标识，真实订阅只显示授权摘要，隔离来源按权限显示合成原文、摘要和已发布画像。验收覆盖来源筛选、切换工作区、单来源断开时独立同步、重开按原游标补拉和重复同步去重。悬浮窗提醒跳回正确来源的会话。撤销真实订阅后隔离来源仍可用，更换隔离连接身份后旧消息和画像被清除。真实订阅在验收后已撤销。

Windows 隔离测试实例已用候选包验证自动切换，并注入启动失败验证恢复上一版本。桌宠已构建使用测试密钥签名的 Windows 0.1.22 安装包，签名已绑定版本，修改文件内容后校验失败。首次自动开发运行到任务时限，独立检查还发现了候选的时区边界错误。已补上上海周一零点和话题范围的回归检查。待完成真实 QQ 自动发布全流程、服务切换时的收件交接、聚合提醒和安装升级的数据联调。

后续隔离任务用真实模型生成了本周话题空结果提示的改动，通过独立验收、构建和测试实例发布，并核对了生效构件摘要。桌宠标准测试包在本机 Windows 同时读取两个订阅来源，用个人模型生成带来源的工作区简报。两个窗口均通过撤权和延迟响应的回归验收。标准包和离线包的提取运行时均通过从 0.1.21 升级的数据兼容测试。

使用测试发布通道的 0.1.21 桌宠从更新界面发现 0.1.22，把更新安排在下次启动。重启后桌宠下载安装包，检测到文件被修改并拒绝替换。隔离 Windows 发布实例验证了切换后恢复、回滚后恢复、发布回执重建及回滚回执重建，均重新核对了在运行的版本。

桌宠 0.1.23 测试包在 Windows 按来源筛选两个服务的开发任务，用目标实例的凭据提交，并在来源断开后恢复查看。会话功能目录展示本周话题，验证了最低客户端版本、会话撤权和服务回滚后移除入口及已展开内容。

桌宠安装包已在 E 盘实际完成 0.1.21 到 0.1.23 的安装、覆盖升级及卸载。应用内更新已下载并安装有效签名的版本，升级后重开保存了两个工作区来源并从原游标继续同步。核对了角色、个人记忆、聊天、模型和订阅凭据、群关注及用量记录。新版本无 WebView2 主机的首次启动仍待验收。

真实群的显式联网查询已核对网页工具记录、DSH 用量和 QQ 送达，回复附有官方资料链接。首条独立创作请求触发了不必要的同群检索，模型超时后送达兜底消息。随后简写「桌游开场白」在约 7.7 秒内取得 QQ 回执，但只回复了「这句可以」，仍触发了同群检索。0.1.58 补齐省略动词的独立创作，保留当前请求、角色和可引用画像，明确引用先前群聊时继续检索。短句已通过真实模型隔离复测，部署后 26 秒通过 12 次健康检查。后续从真实群回执核对答复正文和检索记录。

0.1.71 已部署角色主动空间互动，12 次健康检查通过。使用真实模型和仅自己可见的临时动态各执行一次试演与自动评论。试演生成建议且无平台写入，自动评论取得平台编号并从 QQ 读回，两轮均有实际模型用量。测试后删除临时动态、关闭自动规则并恢复原账号权限。自动点赞和跳过由模拟网关回归覆盖。全量回归 100 项通过、1 项跳过。

需要让群机器人参考该群过去的话题时，可对已开启摘要的群启用「历史召回」或加入 `recallGroups`。每轮从同群、发问前已归档的内容中选取最多两个相关话题。标题和别名优先，常见的口语同义说法也参与匹配。「上周」「昨天」等相对日期按群时区定位。没有说出话题、只追问最后时间时，可以用同群引用或该发言者上一轮问题寻找主题。

确认历史决定时优先使用仍有证据支撑的最近决定，并附最多两条脱敏原话供模型核对。关键证据失效时，旧决定与旧概要不进入回复资料。明确追问单个话题的最后决定且没有相关近期线索时，服务直接提示无法核实。纯文字旧摘要的首尾原文仍可用时可以作为线索。历史召回默认关闭。

QQ 群成员撤回消息后，服务收到平台通知即移除群归档中的对应原文，以及当前对话中引用该原文的材料。正在使用旧资料生成的回复会取消。受影响的摘要概览会标注证据缺口，仍有原文支持的结构化进展可继续查看。独立收件在主服务暂停期间也会记录撤回通知，随后的断线补收会跳过对应消息。

受影响的桌宠工作区在下一次在线同步时重建缓存，最多补回最近 400 条仍有权查看的资料。仅摘要订阅只在其摘要证据变化时重建，已展开的旧摘要功能结果随版本失效。以撤回原文为证据的已发布画像和待审稿会失效，独立的手工画像可继续读取。

明确向机器人追问单个话题的最后日期或时间时，如果归档决定与同群原话能核对到同一个时间，会直接用一句话报出确认结果。归档后同群有明确的新确认时，会注明来自群友消息。涉及「上周」等明确时间范围的追问，只从这个时段召回证据和确认记录，紧接着的短追问沿用同一范围。同群新提议仍作为待定资料交给模型。后台回复追踪区分按归档回答、按新消息回答和证据缺失。

## 早期 Windows 首装与升级

在已安装 WebView2、当前 Windows 配置文件尚无本应用安装记录的图形会话中，以下命令会运行两个实际安装器。程序和测试数据使用项目盘的临时目录，安装器使用无快捷方式的静默模式。

```powershell
node .\scripts\test-windows-desktop-app.mjs .\dist-release\windows-0.1.18\OHJingJing_0.1.18_x64-setup.exe `
  --previous-installer .\dist-release\windows-0.1.17\OHJingJing_0.1.17_x64-setup.exe
```

已通过 0.1.0 至 0.1.9 的逐版首装、同目录升级和卸载验收。覆盖升级保留角色、模型配置、群订阅、聊天、个人记忆和用量。0.1.7 升级至 0.1.8 后，旧版保存的关注群迁移到本机数据库。0.1.8 升级至 0.1.9 后核对了关注群和 Windows 凭据。新版可继续用保存的模型 Key 和订阅令牌连接本机模拟服务。卸载移除程序及 Windows 应用列表中的注册项，并保留指定的数据目录。

0.1.18 标准包和离线包分别在已安装 WebView2 的本机 Windows 会话通过了 0.1.17 首装、实际安装器覆盖升级和卸载。升级后读回角色、个人记忆、聊天、用量、已关注群及授权摘要，原有模型 Key 和订阅令牌仍可用。卸载后程序和 Windows 应用登记已移除，指定数据目录可继续读回。两个包内置的 Node.js 和应用运行时逐项校验一致。

0.1.26 至 0.1.27 用本机更新源和测试签名验收了应用内升级。更新交接前旧版结束了正在同步的桌宠运行时。新版打开后恢复了个人记忆、角色、Windows 凭据、两个服务来源、工作区筛选、提醒设置和同步游标。下次启动安装流程拒绝了篡改包，原应用继续可用。0.1.27 标准包和离线包在已有 WebView2 的 Windows 上各通过安装、首次启动、卸载和 20 项运行时验证，离线包内置的 WebView2 安装程序通过 Microsoft 签名校验。使用 `--fresh-install` 可单独复跑安装、启动和卸载。

在系统和当前用户均未安装 WebView2 的 Windows 图形会话中，使用 `node scripts/test-windows-desktop-app.mjs '<安装包路径>' --fresh-webview2` 验收干净首装。参数接收标准包或离线包，两种包分别从干净环境开始。脚本在运行安装器前检查运行时登记和文件，首次启动时核对测试配置加载的运行时版本，随后卸载桌宠。通过 `OHJINGJING_TEST_DESKTOP_DATA_ROOT` 指定测试安装和数据目录。

0.1.7 已在安装有 WebView2 的 Windows Server 测试机通过图形安装验收。向导创建了开始菜单和桌面快捷方式，两者均指向所选安装目录。通过桌面快捷方式启动后，核对了应用窗口和 WebView2 数据目录。卸载移除了两个快捷方式、程序和 Windows 应用登记。

图形验收可在已登录的隔离测试环境中复跑。脚本要求当前账户没有本应用安装记录，工作目录只用于本次验收。

```powershell
$testRoot = New-Item -ItemType Directory -Path .work -Force
$work = New-Item -ItemType Directory -Path (Join-Path $testRoot.FullName ([guid]::NewGuid().ToString('N')))
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows-graphical-install-probe.ps1 `
  -Installer .\dist-release\windows-0.1.9\OHJingJing_0.1.9_x64-setup.exe -WorkDirectory $work.FullName
```

0.1.9 提供两个 x64 安装包，使用同一套桌宠程序和安装登记。标准包约 23 MiB，需要时联网下载 WebView2 引导程序。文件名以 `-offline-setup.exe` 结尾的离线包约 307 MiB，已内置经 Microsoft 签名的 WebView2 Evergreen 安装程序。目标电脑已有 WebView2 时，两个包都会使用现有运行时。 [Microsoft WebView2 分发说明](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)

构建离线包时，在项目根目录运行 `npm run build -- --config src-tauri/tauri.offline.conf.json`。构建电脑需要联网获取运行时。将 `src-tauri/target/release/bundle/nsis` 下的安装程序以 `OHJingJing_<版本>_x64-offline-setup.exe` 保存到对应的发布目录。

0.1.9 的离线包已在从空盘安装的 Windows Server 2022 图形虚拟机通过验收。安装前确认 WebView2 无登记、无程序文件且网卡断开。向导装入 WebView2 158.0.4370.33，创建了开始菜单和桌面快捷方式。桌宠经桌面快捷方式启动并初始化 WebView2 数据。卸载移除了程序、两个快捷方式及 Windows 应用登记。已在现有 Windows 图形环境核对离线包中的桌宠功能，并验证其运行时读取 0.1.8 数据。

标准包已在另一台从空盘安装的 Windows Server 2022 图形虚拟机通过联网首装。确认运行时缺失后才连接网络，向导下载并装入 WebView2 158.0.4370.33，桌宠经桌面快捷方式启动。卸载清理了两个快捷方式、程序和 Windows 应用登记。标准包的联网引导程序也通过了 Microsoft 签名校验。

在未预装 WebView2 的电脑执行图形验收时，加上 `-RequireMissingWebView2` 核对安装前后状态。软件模拟的虚拟机可使用 `-TimeoutMultiplier 6` 延长探针等待时间。
